## Current status

Maurice is an Android-first household app connected to Home Assistant, with scoped switch UI and otherwise read-only observations. The native foundation and 2D plan work on the Pixel. Kasa and Petlibro read-only integration evidence is recorded. The 2D/3D production view uses saved placements. The demo lamp can be controlled; M01 adds explicit per-device permission and direct summary On/Off. Trial **1009** is accepted on Pixel 9 Pro for the enrolled household lamp, including user-observed On/Off with the original Off state restored. Earlier Maurice Trial build 1002 is accepted on Seeker and Pixel 9 Pro without Metro, with the public sample and a 2D/read-only scope. Other controls, camera images, S02 production-3D acceptance on Pixel and public distribution remain open.

## Delivery order

The user confirmed **daily use in their own home** as the first MVP. The [2026-10-19 household review](reviews/2026-10-19-household-mvp-review.md) defines the scope and implementation handoffs. The [older CEO review](superpowers/specs/2026-10-15-maurice-ceo-review.md) and [2026-10-17 review](reviews/2026-10-17-global-review.md) preserve the earlier rationale; checkpoint, standalone trial and automation foundations have since been delivered.

1. **M00 — source and scoped Seeker acceptance delivered:** web remount and native exposure are corrected; speech is confirmed on 1007. Final M00 application CI passes on e05d88e; keep broader accessibility scope separate. Keep source, browser and native evidence separate. Independent implementation can advance while manual acceptance waits.
2. **M01 — delivered for the enrolled lamp on Pixel 1009:** per-profile/per-device permission, shared dispatch enforcement and direct summary controls pass source/native checks. The user observed the authorized On/Off cycle; original Off state and scoped permission survive restart. The [ledger](stage0/power-enrollment-validation.md) keeps exact-binary and physical evidence separate.
3. **M02 — personalize the household:** explicitly select/apply the real profile plan, link rooms, place the two proven devices, curate visible readings and favorites. Private geometry stays out of shared builds/captures.
4. **M03 — a polished daily Home:** recognizable house preview, useful favorites and shorter primary-control access; collapse routine explanations while keeping meaningful uncertainty and cache/error states.
5. **M04 — accepted spatial presentation:** reuse S02, choose enabled features explicitly for the household candidate and accept its 3D/lifecycle/performance on the target phone. Pixel S02 remains separate until that target is accepted; 2D/list fallback remains available.
6. **M05 — seven days of actual use:** record useful visits/actions, vendor-app returns, confusing states and native failures. Verify HA availability; H02 becomes necessary if the Mac host blocks use. Moving origin requires explicit preference migration and separate authentication.

R01 tooling/native follow-up advances independently; raw findings remain visible under the expiring private-tooling policy, while strict public-release audit stays blocking. R03b public distribution, additional controls, camera images, iOS and widgets follow the household MVP and their own capability/acceptance work. U02 begins with representative measurements rather than a speculative list rewrite. No new vendor clients, app backend or account system is required for this scope.

## Updating the documentation

When completing a ticket, update its status/evidence in `BACKLOG.md` and the affected row here. Change the README if visible behavior or setup changed; change the spec if a contract changed. Add dated evidence to the relevant validation report with the tested scope and limitations. Preserve old results rather than replacing their numbers with a newer test count.

Use only public sample data in committed fixtures, builds and captures. Private plans, identifiers, tokens, full HA payloads and personal validation artifacts stay ignored. An exported bundle prepared with the personal plan **contains that plan**; choosing demo mode does not sanitize the artifact.
