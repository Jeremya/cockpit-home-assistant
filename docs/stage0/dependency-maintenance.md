The upstream [decoder advisory](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr) identifies 0.5.0 as patched. A bounded local subprocess calling the **installed `query-string.parse`** reproduces excessive processing on `key=` followed by 4,000 invalid continuation bytes: the pre-fix process is terminated at two seconds. `npm run proof:dependencies` now checks the installed consumer/version, Unicode, plus signs, repeated values, round trips and three long malformed inputs inside a child process with a five-second limit. Three Jest regressions use the actual Expo Router fork called by the app's linking configuration. Expo's URL search handling replaces invalid UTF-8 before matching; a raw-consumer reproduction is **not evidence that this precise malformed deep link exploited Maurice before the fix**. The vulnerable consumer is nevertheless present in delivered routing code and is now corrected at its dependency boundary.

## Native startup investigation

The preserved incident is a Seeker / Android 16 development-client cold start at 08:54:12, process uptime five seconds, `mqt_v_js`, `SIGSEGV / SEGV_ACCERR`. The first frame is non-executable heap memory; the next is `MountingCoordinator::pullTransaction(bool) const+524`, followed by Fabric scheduling/mounting. `libreactnative.so` Build ID: `e59970ac57f947b8fe2e1ffcdcc218fa16367ed2`. Raw logs remain ignored; no household data or installation paths are published.

Controlled sequence: force-stop the app, start the same development-client URI through adb on Metro 8082, verify Home, and compare the crash buffer. **10/10 starts pass before maintenance and 10/10 after**, with the saved HA profile still readable and zero new native crashes. Background services were not commanded.

The ARM64 debug Gradle rebuild passes with JDK 17, Hermes and Fabric enabled. Updating with `adb install -r` preserves the existing data. The rebuilt APK SHA-256 is **identical** to the installed baseline: `4ab43a6bc85a918b3b1e69864b6aecea797359bf9132007bc72c210f0a0567b0`. These changes do not change the native payload; post-fix runs use a cleared Metro cache and the updated JavaScript. This is not a standalone APK acceptance or an independent native crash correction.

The incident remains **unreproduced, cause unknown**. Do not disable Fabric, change RN major versions, or attribute the failure to a feature without a reproduction. R03a must test its exact standalone binary without Metro; if the crash recurs, retain its artifact hash, native Build IDs and sanitized trace, isolate startup surfaces/animation/library changes one at a time, and resolve it before accepting that artifact. A matching upstream fix must be tied to the reproduced stack/configuration and revalidated.
